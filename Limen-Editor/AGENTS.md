# Limen Editor 协作规范

本文件适用于 `Limen-Editor/` 及其子目录，补充仓库根目录的 `AGENTS.md`。根目录关于授权、所有权、文件编码、验证和架构分层的规则继续有效；本文件规定正式 Editor 与游戏交付主线的协作和架构边界。用户在当前对话中的明确要求优先。

## 1. 项目边界与当前事实

- `LimenEditor` 是独立的 C++ 客户端；正式 Editor UI 走 C++ 自研路线。C# 是未来游戏脚本 1.0 的计划，不用于实现 Editor UI。
- `LimenSandBox` 的 ImGui 是调试和渲染回归工具，不是正式 Editor 的面板系统。参考 UE 的工作流、窗口和停靠理念，不照搬其代码或假装已有同等能力。
- 回答前重新检查相关磁盘文件。当前可确认的起点是：`EditorApp.cpp` 创建应用；引擎的 `Application::Run()` 在 `Layer::OnUpdate()` 之后清理默认窗口帧缓冲，再调用 `Layer::OnUIRender(Window&)`，最后呈现窗口。Editor 是否已经注册 UI Layer、绘制了控件或具备多窗口能力，必须以回答当时的代码为准。
- 区分“已经实现”“本步要实现”“后续设计”。`Limen-Editor/README.md` 中的 Editor 会话、面板、停靠和多窗口是架构目标，不得把设计图里的名称当成现有类或接口。

## 2. 以可用 Editor 能力交付

默认以根目录 `README.md` 的 G0–G4 验收节点组织 Editor 工作，不把控件、布局和停靠本身当作最终成果。每个工作包先核对现有代码，再说明要交付的用户操作、关键架构选择、准确文件范围、与 Engine 的依赖、测试方法及未解决风险；完成后报告实际结果。不要强制套用 WHAT/WHY/HOW 教学模板，也不默认提出理解检查问题。

当前分工是用户亲自编写生产功能，Codex 负责获授权的测试代码、设计核对和代码审查；“继续”不自动授予修改生产文件的权限。用户明确授权 Codex 修改文档、测试或功能时，只在授权范围内实施。若用户主动要求“带我写”或询问概念，再按需要解释 WHAT、WHY、HOW，但以一个可编译、可验证的工作包为单位，不人为拆成只讲一行代码的课堂步骤。

提出新文件时给出完整路径、所属层、调用点、构建接线和验收方式；解释非显而易见的坐标、状态和资源生命周期。避免大段省略关键语句的伪代码，也不要把控件绘制、输入路由、场景数据、停靠和多窗口无依据地一次堆进同一改动。用户修改后说“继续”，必须重读相关磁盘文件，不照搬旧方案。

## 3. 必须讲清 Editor 与 Engine 的联动

讲一个 Editor 功能时，至少交代相关的上下游，而不只展示某个面板内部的代码：

- **输入与帧调度：**原生窗口事件如何进入 `Application`/`Layer`；何时更新数据、何时提交绘制、何时 `Present`；焦点和事件由谁处理。
- **编辑数据：**面板展示或编辑的是哪份 Scene、Asset 或选择状态；谁拥有实际数据，谁只借用；修改是否经过可验证的编辑操作。不要让 UI 组件暗中拥有或释放 Scene，也不要把当前数组下标句柄说成稳定对象 ID。
- **渲染与视口：**场景由 `SceneRenderer` 等引擎组件处理；Editor 的 Scene 视口消费其结果，普通面板不负责场景渲染。需要说明场景颜色纹理、UI 绘制和窗口呈现各处于哪个阶段，不把 Sandbox 的 `ImGui::Image()` 当成正式 Editor 方案。
- **资源与窗口：**解释 CPU/GPU 资源和图形 Context 的创建、借用与销毁顺序。涉及尺寸时区分逻辑窗口尺寸与帧缓冲像素尺寸；涉及离屏场景时确认回到窗口目标后的视口、深度和混合状态。多原生窗口及 Context 共享目前仍是待设计与验证的能力。

UI 的**数据或布局更新**可以由变化触发，不等于每帧重算；但当前主循环每帧清屏并呈现，**可见结果仍需在呈现前提交或复用**。不要笼统说“UI 不更新，所以不需要渲染”，也不要把正式 UI 默认塞入 `OnUpdate()`。若以后引入缓存或保留式 UI，须明确失效条件与最终合成阶段。

对同名但职责不同的概念，要主动辨析：原生窗口、停靠面板、Scene 视口、Editor 会话、UI 组件、Scene、Framebuffer、RenderPass 和图形 Context 不是同一个对象。参考 UE 时，说明借鉴的是哪项交互或架构思想、Limen 已具备的基础是什么、尚缺什么。

## 4. 落点、所有权与验证

- Editor 专用的应用入口、面板、布局和编辑状态优先放在 `Limen-Editor/`；只有确有跨客户端复用需求、职责稳定的能力才考虑进入 `LimenEngine/`。引擎公共接口不得暴露 OpenGL、DX12 或 Metal 原生类型。
- 审查新接口时明确调用者、调用时机、参数单位/坐标空间、返回值和失败含义。明确 `Scope`、`Ref`、引用及非拥有指针的选择；不要因“未来可能共用”就提前共享所有权。
- 需要日志时记录重要状态变化或失败原因，不在每帧 UI 回调中刷日志掩盖问题。测试代码若由 Codex 编写，也要与生产代码的用户编写部分分清。
- 优先从仓库根目录使用现有 CMake Preset 编译 `LimenEditor`；运行验证除“窗口能启动”外，还应给出本步预期画面、输入行为或断点位置。依赖 Shader/Asset 时验证 Editor 自身能找到资源，不以 Sandbox 的复制步骤成功作为 Editor 已正确配置的证明。
- 不手动修改根目录 `.gitmodules`。新建或修改的自有文本文件遵循仓库 UTF-8（无 BOM）规则。

完成一个工作包后，报告**实际改了什么、实际验证了什么、仍未验证什么**；不能把编译通过当成 UI 视觉或交互正确，也不能把单窗口 PoC 当成多窗口 Editor 已完成。
